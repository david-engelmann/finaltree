# finaltree contract

This contract is the executable spec for finaltree. Every obligation below maps to at least one named test in the test suite. An obligation is met only when its tests pass.

## The boundary

Finaltree asks what a gate ran on. Deadgate asks whether it ran, and blindgate asks what it read. Finaltree fingerprints the exact tree a gate ran on, binds that fingerprint to the evidence the gate reports, and verifies the fingerprint against a candidate tree before a verdict from the gate is trusted.

## Probe findings

The readings below rest on probes run against git on this machine with synthetic repos built for the check. The probes built a clean repo, a repo with staged but uncommitted changes, a repo with staged and unstaged and untracked changes standing together, a repo with a staged rename, a repo with a deleted tracked file, and a repo with an ignored build output folder.

Status in porcelain version 1 form with renames disabled reports a staged change in its first column and a worktree change in its second column, so one file can stand as both staged and modified at once and the two facts are separate entries in the reading. Untracked files carry question marks in both columns. A staged rename under the same flags reports as a deletion of the old path and an addition of the new path, and never as a paired record this slice must parse. A deleted tracked file reports as a worktree modification whose kind this reading names as modified.

The file list from ls-files names the paths in the index, and a staged addition stands in that list before any commit holds it, while the tree listing of HEAD names only what the last commit holds. A fingerprint of the tree a gate ran on therefore takes its tracked paths from the index and never from HEAD alone. Hash-object hashes the content of the file in the working tree. On the staged and modified probe file the hash-object result differed from the blob the index held, because the file had changed again after staging, and hash-object failed outright on the deleted file. The tracked blob in this reading is the hash of the working tree content, and a deleted tracked file carries no blob.

Status with untracked files shown still omits ignored files, and the ignored listing collapses an ignored folder into one folder entry. A generated artifact under an ignore rule is therefore invisible to every status reading, and the generated member of this reading is found by walking the files under the root and matching the declared patterns against them.

## Slice 2 obligations

- FT2-1 The fingerprint holds the HEAD commit of the tree. The commit is read with git rev-parse HEAD. A tree whose repo holds no commit is refused with a clear error and never fingerprinted with an empty commit member. Proven by test_fingerprint_holds_head_commit and test_repo_without_a_commit_is_refused.
- FT2-2 The fingerprint holds the tracked files as a list sorted by path. The paths come from the index, so a staged addition stands in the list before it is committed. Each entry carries the git blob hash of the working tree content of the file, and a tracked file deleted from the working tree carries a null blob in its entry. Proven by test_tracked_files_sorted_with_worktree_blob_hashes, test_staged_addition_is_tracked_before_commit, and test_deleted_tracked_file_carries_null_blob.
- FT2-3 The fingerprint holds the dirty files as entries of path and kind, sorted by path and then by kind. The kinds are staged and modified and untracked, read from status in porcelain version 1 form with renames disabled and untracked files shown. A file that is staged and then modified again carries both a staged entry and a modified entry. Proven by test_dirty_entries_name_each_kind and test_file_staged_and_modified_carries_both_entries.
- FT2-4 The fingerprint holds the generated artifacts as a list sorted by path. A generated artifact is a file under the root, outside the .git folder, whose relative path matches one of the declared generated patterns, whether git tracks it, ignores it, or has never seen it. Each entry carries the git blob hash of its content. An untracked file matching a declared pattern stands in the generated list and never in the dirty list as an ordinary untracked file. Patterns are matched with fnmatch rules where a double star crosses folders. Proven by test_generated_artifacts_match_declared_patterns, test_ignored_generated_artifact_is_listed, and test_generated_untracked_file_is_not_an_ordinary_dirty_entry.
- FT2-5 The fingerprint digest is the SHA-256 hex digest of one canonical serialization. The serialization is a JSON object holding the format name finaltree-fingerprint/1 and the commit and the tracked list and the dirty list and the generated list, with object keys sorted, with compact separators, and with every list in the sorted order its obligation states. The same members discovered in a different order give the same digest, and a change to any member changes the digest. The members themselves are retained beside the digest so a mismatch can be named and not just detected. Proven by test_digest_is_canonical_and_order_independent and test_any_member_change_changes_the_digest.
- FT2-6 Stamping binds a gate run to its fingerprint. The fingerprint is computed before the command runs, from the tree the command will run on. The command runs in the root without a shell, and its standard output and standard error are captured together in the order the command produced them. The stamped log carries a header a verifier can read back, holding the stamped log format name, the fingerprint digest, the full fingerprint as one JSON line, the generated patterns in force, the command, and the exit code. Every captured output line is written after a prefix holding the fingerprint digest, so every count line the gate reports is bound to the fingerprint. The stamped log is written even when the command exits nonzero, and the stamping command itself exits with the exit code of the gate command. Proven by test_stamp_binds_output_lines_to_the_fingerprint, test_stamp_writes_the_log_when_the_gate_fails, and test_stamp_returns_the_gate_exit_code.
- FT2-7 Verification answers match or mismatch and names every difference. The verifier reads the fingerprint from a stamped log header and computes the fingerprint of a candidate tree under the generated patterns the log records. The answer is match only when the commit and every tracked entry and every dirty entry and every generated entry agree. On a mismatch the verifier prints one line per differing member, naming a moved commit as a commit move, a changed tracked blob as a file content change, a tracked path standing on one side only as a tracked file added or removed, a dirty entry standing on the log side only as a dirty file cleaned, a dirty entry standing on the candidate side only as a dirty file added, and a generated entry that differs as a generated artifact difference. A generated artifact difference is never also reported as an ordinary file content change for the same path. The verify command exits zero on a match and one on a mismatch. Proven by test_verify_matches_the_tree_the_log_was_stamped_from, test_verify_names_a_moved_commit, test_verify_names_a_changed_file, test_verify_names_a_cleaned_and_an_added_dirty_file, and test_verify_names_a_generated_difference_as_generated.
- FT2-8 A stamped log that does not parse is refused. A log whose header lacks the fingerprint record, or whose fingerprint record does not decode, or whose recorded digest disagrees with the digest of its recorded members, or that carries an output line without the digest prefix, is refused with a clear error and the verify command exits two. Proven by test_verify_refuses_a_log_without_a_fingerprint_record and test_verify_refuses_a_log_whose_digest_disagrees_with_its_members.
- FT2-9 Fingerprinting and verification write nothing into the tree they read. Stamping writes only the stamped log at the path it is given. No operation in this slice uses the network. Proven by test_fingerprint_and_verify_leave_the_tree_unchanged.

## Round 1 review fixes

The slice 2 readings were audited before the round closed by an independent red team and by an independent two axis review. The red team returned a rejection on one Critical finding and two Major findings, with eight Minor findings standing behind them, and the two axis review returned a conditional pass on the spec axis and a conditional pass on the standards axis, with no Major finding on either axis. The Critical finding and the Major findings sat in the honesty of the fingerprint itself, in what the fingerprint left unbound and in what a stamped log let a reader rewrite without detection. The amendments below answer the findings one by one, in the order the findings were listed for the fix pass, and each amendment names the obligation it amends. The slice 2 text above stands unaltered as the record of what was first built, and where an amendment and the slice 2 text disagree, the amendment is the reading the code follows. The probe readings the amendments rest on were run against git on this machine with synthetic repos built for the check, and each amendment names the probe it rests on where it rests on one.

- FIX-1. The index stands in the fingerprint, amending FT2-2 and FT2-3, and answering red team Critical 1 and two axis Note A-5. A tracked entry now carries the blobs the index holds for its path beside the blob of the working tree content, one blob per index entry for the path in stage order, read from ls-files in stage form, which a probe on a staged and then modified file showed reporting mode and blob and stage for every index entry while the working tree hash stood apart from the staged blob. Restaging different content while the working tree is restored to the same bytes therefore changes the fingerprint, and a log stamped on the earlier staging no longer verifies against the later one. Verification names an index difference as an index content change, standing beside the file content change the worktree blob carries. The limit the slice 2 probe account stated by construction, that staged content is not separately retained, is retired by this amendment and stands nowhere in the reading. The format name stays finaltree-fingerprint/1 and the tracked entry gains the index blobs inside it, because the slice has not landed and no reader outside this repo has read the earlier shape. Proven by test_index_blob_stands_beside_the_worktree_blob, test_restaged_content_changes_the_fingerprint, and test_verify_names_an_index_difference.
- FIX-2. The stamped log covers its own claims, amending FT2-6 and FT2-8, and answering red team Major 2 and Minor 7 and two axis Minor A-3. The header of a stamped log now carries an evidence digest, the SHA-256 hex digest of the command line as written and the exit code line as written and the output lines as written, taken in that order and joined by newlines. The reader recomputes the evidence digest from the lines it read and refuses the log when the recomputation disagrees, so an edited count line and a deleted output line and a forged output line and a rewritten exit code are each a refusal and never a match. The header fields FT2-6 names are required on read with no silent defaults. The fingerprint line must stand and must equal the digest of the fingerprint record, the fingerprint record must carry its digest and that digest must agree with its members, and the command line and the exit code line must each stand. A log carrying content after the output section closes is refused, and a header line standing twice is refused. The format name stays finaltree-stamped-log/1 and the header gains the evidence line inside it, because the slice has not landed and no reader outside this repo has read the earlier shape. Proven by test_stamped_log_carries_an_evidence_digest, test_verify_refuses_a_log_with_an_edited_count_line, test_verify_refuses_a_log_with_a_deleted_output_line, test_verify_refuses_a_log_with_a_forged_output_line, test_verify_refuses_a_log_with_a_flipped_exit_code, test_verify_refuses_a_log_without_a_fingerprint_line, test_verify_refuses_a_log_whose_record_carries_no_digest, test_verify_refuses_a_log_without_an_exit_code_line, test_verify_refuses_a_log_without_a_command_line, and test_verify_refuses_a_log_with_content_after_the_output_section.
- FIX-3. Untracked content is bound, amending FT2-3 and FT2-4, and answering red team Major 3. The fingerprint now holds the untracked files as members of their own, each carrying the hash of its content beside its path, gathered from the same status reading that names the untracked kind, with any file standing in the generated list left out so no file is counted twice. Changing the content of an untracked file changes the fingerprint, and a file removed from the index and left standing in the worktree is bound by its untracked member, so rewriting it after its removal from the index changes the fingerprint where the earlier reading saw only the same two dirty entries. The dirty entries keep naming untracked presence as before, and verification names an untracked content change on a path standing in both untracked lists, while a path standing on one side only is named by the dirty section as before. No size limit is adopted, and a path that is neither a file nor a link carries a null blob in its untracked member, as a deleted tracked file does in its tracked entry. Proven by test_untracked_content_change_changes_the_fingerprint, test_rewrite_after_rm_cached_changes_the_fingerprint, and test_verify_names_an_untracked_content_change.
- FIX-4. A link stands as itself, amending FT2-2, and answering red team Minor 5. The blob a member carries for a path that is a symbolic link is the blob of the link itself, the hash of the target path the link names, computed by hashing that target path through git as the index itself records it. A probe showed hash-object following the link to the content of its target while the index entry for the same link held the hash of the target path itself, and hashing the target path through git reproduced the index blob exactly. A broken link therefore carries the hash of the target path it names and never the null blob a deleted file carries, and the two stand apart in the members. The reading holds for the tracked worktree blob and for the untracked and generated members alike. Proven by test_symlink_tracked_blob_is_the_link_itself and test_broken_symlink_stands_apart_from_a_deleted_file.
- FIX-5. Patterns mean what FT2-4 says, amending FT2-4, and answering red team Minor 6 and two axis Minor A-1. A pattern is matched against the relative path of a file as a whole, under glob rules where a single star matches any run of characters within one folder and never crosses a folder boundary, a double star matches any run of characters across folders, a question mark matches one character within a folder, and a bracketed list matches the one character it lists. The fallback the earlier code kept, matching the base name of a file against the pattern when the path did not match, is removed, because the contract never promised it and it widened every bare name into every folder. Proven by test_single_star_stays_within_one_folder and test_bare_name_pattern_matches_no_nested_file.
- FIX-6. The root is the top level and a conflict reads as a conflict, amending FT2-1 and FT2-3, and answering red team Minors 8 and 9 and two axis Note B-6. Fingerprinting a root that is not the top level of its working tree is refused with the standing error kind, and the refusal names the top level the root stands under, read with rev-parse --show-toplevel, which a probe from a subdirectory showed naming the top level of the tree the subdirectory stands in. A path standing unmerged in the index reads in the dirty list with a conflicted kind of its own and never as a staged entry and a modified entry standing together. A probe of a merge conflict showed status reporting the path with U in both columns and the stage form of ls-files holding three stage entries for it and no stage zero entry, and the tracked entry for such a path carries those stage blobs under FIX-1. Proven by test_subdirectory_of_a_tree_is_refused and test_conflicted_file_reads_with_a_conflicted_kind.
- FIX-7. Verification compares whole member lists and names tracked additions and removals, amending FT2-7, and answering two axis Minors A-4 and A-2 and red team Minor 11. A fingerprint record carrying the same path twice in one member list, or the same path and kind twice among the dirty entries, is refused when the record is read, so no duplicated member can collapse silently inside a dictionary comparison. Verification compares the member lists as the lists they are and names a tracked path standing on the log side only as a tracked file removed and a tracked path standing on the candidate side only as a tracked file added, the naming FT2-7 always carried and the suite now pins. The sentence in FT2-7 on generated differences is restated to say what the code does, that a generated difference on a path suppresses the tracked comparison for that path, so the generated section alone names what changed there. The generated difference pin that stood on an untracked file, where the rule against double naming could never be exercised, is rebuilt on a tracked generated file as a named mechanical consequence of this amendment. Proven by test_record_carrying_a_member_twice_is_refused, test_verify_names_tracked_files_added_and_removed, and the rebuilt test_verify_names_a_generated_difference_as_generated.
- FIX-8. The remaining pins are completed and a path git cannot spell in UTF-8 is refused, amending FT2-2, and answering two axis Minors B-1 and B-2. The merged capture of standard error beside standard output now stands pinned with a gate command that writes to both. A change of standing alone, the same content unstaged and then staged, stands pinned as changing the digest with the content held equal. The digest now stands pinned as ignoring the order of every member list, the generated and untracked lists beside the tracked and dirty lists. The refusals of FT2-8 for a fingerprint record that does not decode and for an output line carrying no digest prefix now stand pinned. A path that git spells with bytes that are not valid UTF-8 is refused with the standing error kind when the fingerprint is computed, because the canonical serialization carries text and such a path cannot stand in it truthfully, and a probe showed ls-files in the null separated form handing such a path back as raw bytes with no quoting. Proven by test_stamp_merges_stderr_into_the_output, test_staging_the_same_content_changes_the_fingerprint, test_digest_ignores_the_order_of_every_member_list, test_verify_refuses_a_log_with_an_undecodable_fingerprint_record, test_verify_refuses_an_output_line_without_the_digest_prefix, and test_path_spelled_with_non_utf8_bytes_is_refused.
- FIX-9. The standards sweep, answering two axis Minors B-3 and B-4 and Note B-5, with no change to any reading. The walk helper stands private at module top with its import at module top beside the others. The record a fingerprint emits now lists every member list in the canonical order and shapes its entries through the one shaping the canonical serialization uses, so the emitted record and the digest can no longer drift apart. The no commit test drops its inline import and its unused alias. The setup pin for AGENTS.md now pins the sentences of the annex in their standing order after the manner of the catchledger pin, because a test inside this repo cannot read the canonical template file of the program from an archive extraction of this repo alone, and the identity of the part above the marked line with the canonical template is verified by the owner at landing and stated as such here. Proven by test_record_dict_emits_members_in_canonical_order and the strengthened test_agents_md_stands_from_the_canonical_template.
- FIX-10. The claim of the fingerprint is scoped to its members, amending the boundary claim and FT2-3, and answering red team Minors 4 and 10. The fingerprint identifies a tree through the members it binds, the commit and the tracked content of the working tree and of the index and the dirty kinds and the untracked content and the generated artifacts, and two standings sit outside it as stated limits. An ignored file matching no declared pattern stands outside the fingerprint entirely and leaves no entry of any kind, so a gate reading such a file holds evidence this tool does not bind, and a declared pattern is the way to bring such a file inside. A stamped log belongs outside the tree it stamps, because a log written inside the tree is itself a change to the tree and the next verification names it as one, honestly and by its path. No code change rides on this amendment beyond what the statements require. Proven by test_readme_states_the_limits_of_the_fingerprint.
